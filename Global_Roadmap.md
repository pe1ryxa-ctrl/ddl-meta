# Danger Drones Lab (DDL) — Global Roadmap

Цей документ слугує високорівневою стратегічною дорожньою картою для всієї екосистеми DDL (Server, STC, SRC, DAI). Він підтримується L2 Архітектором і забезпечує єдине бачення напрямку розвитку проєкту.

## Поточна Пріоритетна Послідовність

Наступні фази мають виконуватися у суворій послідовності. Усі інші майбутні покращення заморожені до повного завершення цього списку.

### ✅ Фаза 1: Стабілізація та Аналітика (DDL Server) [ЗАВЕРШЕНО]
- **Мета:** Накопичення статистики використання сайту, моніторинг продуктивності та оперативне виправлення знайдених помилок.
- **Відповідальність:** Команда DDL Server

### 🟡 Фаза 2: Допрацювання та Тестування SRC (SRC Workspace) [АКТИВНО (Тестування)]
- **Мета:** Фіналізація прошивки, відладка протоколів та інтенсивне тестування Smart Remote Control (SRC) на фізичному обладнанні.
- **Статус:** Прошивка `v2.0.0-stable` (з підтримкою 3х VRX, Bind-логікою та розширеним Web UI) зібрана. Очікуються результати польових випробувань від пілотів.
- **Відповідальність:** Команда SRC

### 🔴 Фаза 2.5: Кросс-Проєктні Інновації (High Priority)
- **Мета:** Значний архітектурний та UX апгрейд для обох прошивок (SRC та STC) перед глобальним релізом.
- **Пріоритет 1 (SRC): Multi-Protocol RC Auto-Detect.** Розробка нового менеджера протоколів для автоматичного сканування та визначення RC-протоколу (CRSF, SBUS, F.Port, S.Port) через динамічну реконфігурацію UART матриці (baud rate, hardware inversion) "на льоту".
- **Пріоритет 2 (STC): Уніфікація RC (Backend + UI) та Архітектурний Рефакторинг.** 
  - **Backend (FreeRTOS):** Глибокий рефакторинг архітектури STC для переходу на повноцінну модель ізольованих задач FreeRTOS (відмова від монолітного суперциклу, якщо такий є), щоб відповідати сучасній багатопотоковій архітектурі SRC.
  - **Backend (Protocols):** Портування нового компонента `rc_receiver` (Multi-Protocol Auto-Detect) з SRC у проєкт STC для підтримки SBUS/F.Port/CRSF.
  - **Frontend:** Оновлення вікон вибору RC каналів у STC до нативних `<select>` елементів з підтримкою автовизначення стіків.
  - **Дизайн (Style Unification):** Уніфікація CSS-стилів, типографіки, відступів та логіки мобільних адаптацій у STC для повної відповідності стандартам DangerUI, реалізованим у SRC.
- **Відповідальність:** Команда SRC / Команда STC

### ⏳ Фаза 3: Публічний Реліз SRC (DDL Server)
- **Мета:** Зняття блокувань та відкриття функціоналу SRC на порталі (Магазин, Профіль, Адмінка) після успішного завершення апаратних тестів.
- **Відповідальність:** Команда DDL Server

### ✅ Фаза 4: Інтеграція Спільноти (DDL Server) [ЗАВЕРШЕНО]
- **Мета:** Інтеграція безпечного військового чату на базі FastAPI WebSockets (з масштабуванням через Redis Pub/Sub та кастомною автомобідерацією) замість Matrix Conduit.
- **Відповідальність:** Команда DDL Server

### ✅ Фаза 5: Глобальна Міграція на GitHub [ЗАВЕРШЕНО]
- **Мета:** Перенесення всієї кодової бази екосистеми DDL (Server, STC, SRC, DAI) у приватні хмарні репозиторії GitHub. Налаштування remote-адрес, бекап історії розробки.
- **Відповідальність:** Усі команди (L2 Architect + L1 DDL/STC/SRC/DAI)

### ✅ Фаза 3: Стабілізація DAI Agentic Pipeline [ЗАВЕРШЕНО]
- **Мета:** Оптимізація RAG-краулера, забезпечення стійкості до блекаутів (атомарні збереження), паралельна асинхронна генерація топіків та міграція на `gemini-3.1-flash-lite`.
- **Нотатки:** Успішно додано підтримку парсингу документів Office (docx, xlsx) та покращено безпеку (захист від SSRF, оновлений нормалізатор URL, фільтрація бінарників, включаючи ArduPilot `.abin`, `.rom` та `.bootloader`).
- **Відповідальність:** Команда DAI

---

### ✅ Фаза 6: Оздоровлення конвеєра DAI та облік вартості [ЗАВЕРШЕНО 12.09.2026]
- **Мета:** Привести щоденний конвеєр DAI у стан, придатний до експлуатації, і зробити витрати на LLM вимірюваними.
- **Результат:** Час прогону 14 год 20 хв → 27 хв (усунуто зависання на успадкованих fd). Простій бота з ~14 год/добу → нуль, падіння ловиться за 15 хв. Граф бази знань відновлено: 36 396 галюцинованих посилань відремонтовано, биті внутрішні посилання зведено до нуля, усунуто їх джерело в промпті генератора. Дедуплікація виконана за онтологічними правилами OKF (5 злиттів замість помилкових 6 944 видалень) і захищена від відкату. Впроваджено облік витрат у доларах, бюджетну й токенну стелі; ставку `gemini-3.1-flash-lite` виміряно емпірично — $0.84/1M (збіг зі списанням до цента).
- **Відповідальність:** Команда DAI (задачі DAI-001…DAI-007)

## ❄️ Заморожені Покращення
*(Ці завдання призупинені до завершення активних фаз)*
- **Cloudflare Cache Automation:** Автоматичне очищення кешу при деплої.
- **Admin Security (WebAuthn/FIDO2):** Апаратна аутентифікація для адміністраторів.
- **True Zero-Downtime Deployment:** Безшовне оновлення бекенду (Blue-Green).
- **Pre-encrypted OTA:** Роздача попередньо зашифрованих прошивок.
